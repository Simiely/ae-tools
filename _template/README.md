# 面板模板 PANEL-SKELETON

派生新 AE ScriptUI 面板的起点。**不是可交付的面板**，是一份带约定的骨架。

## ⚠️ 为什么它不在 `panels/` 下

`install.py` 的 `collect_jsx()` 会收集 `panels/` **一级子目录**里的所有 `.jsx` 并部署到 AE。
模板若放在 `panels/_template/`，**会被当成真面板装进 AE 的扩展菜单**。

所以它放在仓库根 `_template/`，`install.py` 不会碰它。

代价：`verify.py` 默认只扫 `panels/*/`，扫不到它 —— 所以 verify.py 里**专门加了模板检查**
（语法 + 跑测试 + 版本一致性）。**没有这一步，模板会腐化**：一年后复制出来的骨架可能是坏的，
而且要等真机报错才发现。

## 派生一个新面板（三步）

```bash
# ① 在仓库根执行脚手架（自动复制 + 改名 + 替换标识 + 生成 CHANGELOG/README）
python new_panel.py MyPanel "我的面板"

# ② 写业务: 把「示例逻辑」段(全文件搜 `示例`)替换成真实逻辑,
#    并把真实的数学/字符串处理放进「纯逻辑层」, 同时补进测试

# ③ 验收 + 部署
python verify.py     # 语法 + 断言 + 部署一致性 + 技术债清单
python install.py    # 部署到 AE(重启 AE 后生效)
```

手动做也可以：复制整个 `_template/` 到 `panels/<面板名>/`，把 `.jsx` 与目录同名，
然后替换两个标识 —— `TOOL_ID`（英文，用于文件名/导出名）与 `TOOL_TITLE`（中文显示名）。

## 骨架里的约定速查

每一条都对应一次真实事故，**不要为了"看起来简洁"删掉**：

| 约定 | 删掉会怎样 |
|---|---|
| 顶部常驻 `v<VER>` + `VER` 常量 | 分不清 AE 里跑的是新版还是旧版；AE 报错行号可能是旧文件的，排查方向全错 |
| 测试导出闸门（位置 + 末尾 `return`） | 纯逻辑层无法在 node 里断言 → 每个改动只能靠肉眼看渲染结果 |
| 所有 handler 经 `safeRun` | AE 的 ScriptUI handler 抛错**静默** → 用户看到"点击没反应"，且没有任何线索 |
| `pinW` 三处都写 | `preferredSize` 是 volatile 属性，首次布局丢失 → 面板"弹宽" |
| `fixedBox` 先钉宽度再钉高度 | `pinW` 会把高度重置为自适应 → 设的高度**静默失效**（本仓库潜伏过 4 个版本）|
| `scrollable` 存在性回退 | 某版本 AE 不认该属性时，面板**直接打不开** |
| 单 Undo 组 + `finally` | 用户 Ctrl+Z 撤一半；中途抛错则 Undo 组永不关闭 |
| 「未激活合成」状态栏 + 弹窗 | 提示只在面板最底部 → 用户以为"按钮坏了" |
| 诊断三件套（`diag`/`flushDiag`/复制） | 真机出错时拿不到任何可反馈的信息 |
| 版本号三处一致（常量 / CHANGELOG / 面板） | 版本号本身不可信，"看版本号判断新旧"这套就废了 |

**前四条是"能不能改得动"，后六条是"坏了查得到"。** 缺前者，开发变慢；缺后者，线上抓瞎。

## 测试里的两类断言

`test_PanelTemplate.js` 有两类，**都要留着**：

- **Ⅰ 业务断言** —— 你写的纯函数行为（派生后往里加）
- **Ⅱ 骨架体检断言** —— 守住上表里的约定本身

Ⅱ 类比 Ⅰ 类更关键：模板会被反复复制，骨架一旦腐化，复制出来的每个新面板都是错的。
