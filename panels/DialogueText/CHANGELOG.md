# 对话文本动画 DialogueText — 变更记录

> 版本号格式：`## vX.Y.Z` 必须顶格 —— `verify.py` 与 `test_DialogueText.js` 都读它来校验一致性。

## v0.11.11 (2026-11-25) —— 选区索引与节奏改用非空白字符序号（修复空格后首字常显）

### 现象（v0.11.10 真机）

- 44 字长句（含 1 个空格）应用逐字出现：动画器 44 个、无任何报错；
- 但**空格后的第一个字「朵」从 0 秒起一直显示**：不参与逐字出现，隐藏阶段也不消失。

### 根因（真机实证）

- 脚本跳过空格不建动画器，但选区值与关键帧时间仍按**原文下标** `i` 排列；
- AE 26 真机实测：**索引单位下空格不占索引**（官方帮助说「依据=字符」会数空格，
  但索引单位的实际行为不数）——
  于是 `DT_渐隐31` 根本不存在，AE 索引 31（第一个「朵」）没有任何动画器覆盖 ⇒ 常亮；
  后续字的索引比实际位置早一拍，最后一个「?」由原来的 `i=42` 顶上。

### 变更

- 新增纯函数 `countVisibleChars(str)`（非空白字符数）并导出；
- `applyTypeScroll`：`visN = countVisibleChars(...)`，时间轴
  `computeTypeScrollTiming(visN, …)`、位置表达式 `buildTypeScrollExpression(visN, …)`
  都按可见字数；`visN` 为 0 时退回原始字数；
- `applyTypewriter(…, visibleCount)`：循环内用 `selIdx`（非空白字符序号，0 基）：
  选区写 `Index Start/End = selIdx / selIdx+1`，关键帧时间 `selIdx × step`，
  动画器命名 `DT_渐隐NN` 也按可见序号；百分比回退同样按 `visN`；
- 日志改为 `N 字(可见 M)`，便于核对空格差异。

### 验收

- `node test_DialogueText.js` → **506 通过 / 0 失败**（新增「二十五、v0.11.11」十五条断言）
- `python verify.py` → 全部通过

### 真机步骤

1. 完全退出 AE 再打开，确认顶部 `v0.11.11`；
2. 选中出问题的段落文本层 → 先「移除动画」清掉 v0.11.10 残留 → 再「应用动画」；
3. 第一个「朵」应按自己的时间逐字出现，不再从 0 秒常显；隐藏阶段整行一起渐隐 + 左移；
4. 展开 `DT_渐隐NN`：Start / End 是连续整数，且 `DT_渐隐32` 存在（对应第一个「朵」）。

> ✅ **真机确认（2026-11-25）**：用户反馈「这次正常了」。
> 说明「选区 / 节奏 / 表达式统一用非空白字符序号」这条链路已经闭环。

## v0.11.10 (2026-11-25) —— 修正索引选区：每个动画器逐个切单位 + 用 Index Start/End

### 现象（v0.11.9 真机）

- `第 1 字: 设置选区失败: Error: After Effects错误: 无法将“set value” 与此属性一起使用，因为属性或父级属性被隐藏。`
- 随后动画器只有 43 个（44 字 / 1 个空格 / 1 个失败），其余字的选区值也不对。

### 根因（两条，都有官方 matchName 依据）

1. **每个动画器都有自己的默认选区**，默认单位是百分比。v0.11.9 只在第一个字切了索引单位，
   后面的动画器仍是百分比，却被写入 `i / i+1` 这样的索引值 ⇒ 选区几乎不覆盖任何字；
2. 切到索引单位后，Start / End 换成另一对属性
   **`ADBE Text Index Start` / `ADBE Text Index End`**（官方 Text Layer Match Names）；
   此时再写 `ADBE Text Percent Start / End` 会报「属性或父级属性被隐藏」——
   这正是第 1 个字失败的原因（选区已切索引，却还在写百分比那对）。

### 变更

- `findSelectorStartEnd(sel, wantIndex)`：按单位精确取对应的一对属性，
  不再用显示名 `Start / End` 兜底（两对显示名完全相同）；
- `setSelectorIndexMode(sel)`：先切 `Units=Index`，确认 `Index Start / End` 存在，
  再设 `Based On=Characters`；取不到就切回百分比（`setSelectorUnits(sel, 1)`），绝不混用；
- `applyTypewriter`：**每个动画器分别切单位**（`var idxMode = setSelectorIndexMode(sel)`），
  按 `idxMode` 取属性并写值；索引不可用时退回百分比，只提示一次。

### 验收

- `node test_DialogueText.js` → **491 通过 / 0 失败**
- `python verify.py` → 全部通过

### 真机步骤

1. 完全退出 AE 再打开，确认顶部 `v0.11.10`；
2. 选中出问题的段落文本层 → 先点「移除动画」清掉 v0.11.9 残留；
3. 再点「应用动画」：不应再出现「设置选区失败」；每个字按自己的时间出现，
   隐藏阶段整行一起渐隐 + 左移，没有常显字。

## v0.11.9 (2026-11-25) —— 已撤回，由 v0.11.10 修正

> ⚠️ v0.11.9 的索引单位只切了第一个动画器，且切完后仍写百分比那对 Start/End，
> 真机报「属性或父级属性被隐藏」。请直接用 v0.11.10。

### 现象

段落文本（框文本）应用逐字出现后，**有两个字从 0 秒起一直显示**：
不按自己的时间出现，隐藏阶段也不跟着消失；其余字符正常。
真机：44 / 46 字，框 614x184 / 627x184，日志一切正常（`段落框无溢出`）。

### 根因（官方 + 社区交叉验证）

- 每字动画器的范围选择器原来用**百分比**：`Start = i/n*100`、`End = (i+1)/n*100`；
- 字符数 n 不能整除 100 时，字符边界落在小数上，AE 按字符边界取整，
  可能把**相邻字一起并进同一个动画器**；被并进来的字沿用第一个动画器的关键帧
  （`t0 → 0`、`t1 → 100`，之后一直 100 到隐藏阶段），于是从 0 秒起就一直可见；
- Adobe 官方《Animating text》写明范围选择器的**单位可选百分比或索引**，
  依据选「字符」时空格也计入；社区通行做法是 `Units: Index` +
  `Start: 0 / End: 1` 精确选中第一个字。

### 变更

- 新增 `setSelectorIndexMode(sel)`：把选区 `Units` 设为 **Index(2)**、
  `Based On` 设为 **Characters(1)**；取不到属性返回 false；
- `applyTypewriter` 每个字设置选区时优先用索引单位：`Start = i`、`End = i + 1`
  （0 基；当时假设「空格也占索引」，该假设后被 v0.11.11 真机否定），
  只在第一个字探测一次；索引不可用时退回百分比并写诊断
  `选区无法切换索引单位, 退回百分比(可能出现相邻字同时显示)`；
- `Smoothness` 仍保持 0，每个动画器仍然只覆盖一个字符。

### 验收

- `node test_DialogueText.js` → **485 通过 / 0 失败**（新增「二十四、v0.11.9」十一条断言）；
- `python verify.py` → 全部通过。

### 真机步骤

1. 完全退出 AE 再打开（面板只在启动时载入），确认顶部是 `v0.11.9`；
2. 选中之前出问题的段落文本层，直接再点「应用动画」（旧动画会先按名称清掉）；
3. 重点看：**不再有从 0 秒起就常显的字**；每个字都在自己的时间出现，
   隐藏阶段整行一起渐隐 + 左移。

## v0.11.8 (2026-11-25) —— 段落文本单行化：你的框就是出现窗口，不再拉高框

### 现象

v0.11.7 把溢出的段落框从 49 拉高到 129px，49 字全部显示出来了，
但用户明确反对：**「原本的文本框被修改了……我给的文本框就是出现字的范围」**，
并要求：**文字不超出框，但仍从右往左出现文字，像程序（终端）一样**。

### 根因与约束（官方）

- 段落文本（框文本）**按框宽自动换行**，超出定界框的行 AE **不渲染**
  （Adobe Help《创建和编辑文本图层》：框外只显示溢出图标）；
- `TextDocument.boxText` **只读**，脚本**不能**把段落文本转成点文本
  （官方说明只能通过右键菜单互转，且转点文本会删除框外字符）；
- 因此 595px 宽、49 字、字号 40.6 的段落文本必然排成 3 行 ——
  「框保持 49 高」与「3 行全部可见」在 AE 里不能同时成立；
  要让整句不换行，**排版框的宽度必须够**。

### 变更

- `fitParagraphBox` 重写：**不再拉高框**，改为**单行化**——
  1. 框高设成「一行高」（`max(原框高, ceil(行距))`，行距缺失按字号×1.2），
     此时 `boxOverflow === false` 等价于「整段排成一行」；
  2. 宽度**倍增**（w→2w→4w…，上限 max(8192, 32w)）找到第一个不溢出，再**二分**到最小一行宽；
  3. 写回 `[一行宽, 一行高]`，复核 `boxOverflow`，失败一律还原原框；
  4. 只写 `boxTextSize` / `boxTextPos`，**不改文字、字体、字号、图层位置**；
- **窗口 = 用户给的段落框**（宽高都不动）：宽高取自原框 `boxTextSize` 与左上角 `boxTextPos`
  （层坐标，与 `sourceRectAtTime` 同坐标系）；点文本仍沿用文字外框；
- 原框尺寸写进蒙版名 `DT_窗口 595x49`（`buildMaskName` / `parseMaskNameBox` /
  `readStoredWindow`）：排版框被加宽后，**重复应用仍按原框当窗口**，
  不会把加宽的排版框误当窗口；`isOurMaskName` 改为前缀判定，清理旧蒙版不受影响；
- 窗口比文字窄时，位置表达式 `dx = br - (rl + avg*ks)`（上限 0）
  自动让整行「打满后左移」—— 即终端式从右往左流动；出现阶段前几十个字
  仍在框内原位逐字出现，打满框后整行左移，隐藏阶段继续左移并渐隐；
- 框高小于一行时（如框高 30 < 行距 49）日志告警：文字上下会被窗口裁掉；
- 强制换行（文本含 `\r`）无法单行化时还原原框并告警，不硬改；
- 旧版 AE 无 `boxOverflow`：保留撑高探测判溢出，再按量到的单行宽度单行化。

### 验收

`node test_DialogueText.js` → **474 通过 / 0 失败**；`verify.py` / `install.py` 通过；
⚠️ **待真机验证**：
1. 先 **Ctrl+Z 撤销一次**（v0.11.7 曾把框从 49 拉到 129，整次应用是单 Undo 组），
   确认框回到 595x49；
2. 应用后日志应为：`⚠ 段落文本溢出: 排版框 595x49 → Wx49px (官方 boxOverflow, 试探 N 次, 1 行), 改为单行; 你的框 595x49 作为出现窗口…`；
3. 画面上文字只出现在你给的 595x49 框内，打满后整行从右往左流动，隐藏阶段继续左移渐隐；
4. 再点一次「应用动画」：蒙版名带 `595x49`，窗口不变，效果一致（幂等）。

## v0.11.7 (2026-11-25) —— 段落框溢出改用官方 boxOverflow(不再依赖测量语义)

### 现象

v0.11.6 的修法依赖 `sourceRectAtTime(t, false)` 在「撑高定界框」后返回**文字范围**。
Adobe 表达式参考只说明 `includeExtents=true` 时段落文本返回**段落框边界**，
并未保证 `false` 一定返回文字范围 —— 若宿主返回的是框尺寸，
v0.11.6 只会走「撑高后测量仍等于框高 → 还原 + 告警」，溢出不会被修掉。

### 官方依据（ae-scripting.docsforadobe.dev / TextDocument，AE 24.6+）

- `TextDocument.boxOverflow`（只读布尔）：**有文字没能排进定界框时为 true**；
- `TextDocument.boxTextSize`：`[宽, 高]`，**可读写**（整数，最小 1）；
- `TextDocument.boxTextPos`：框左上角的图层坐标，可读写；
- `TextDocument.composedLineCount`：排进框里的行数；
- 官方注明 TextDocument 实例是**组合时快照**，改它不会重排 ——
  必须在 `setValue` 之后**重新取 `st.value`** 再读 `boxOverflow`。

### 变更

- `fitParagraphBox` 改为两条路线：
  - **boxOverflow 可用（AE 24.6+，本项目 AE 26.0）**：先读 `boxOverflow`；
    `false` ⇒ 全部文字都在框内，**完全不动用户的框**；
    `true` ⇒ 框高**倍增**（h→2h→4h…，上限 max(4096, 64h)）找到第一个不溢出的高度，
    再在「已知溢出 / 已知不溢出」之间**二分**到最小可容纳高度，写回 `boxTextSize`；
    写回后**再读一次 `boxOverflow` 复核**，仍有溢出或任何失败一律还原；
  - **旧版 AE 没有 boxOverflow**：退回 v0.11.6 的撑高探测法（原逻辑保留）。
- 新增 `restoreBoxPos`：框高变化后把 `boxTextPos` 恢复原值 ——
  AE 若以中心为基准缩放框，文字会跟着跳；恢复框位置保证文字留在原处。
- 应用日志区分：`段落框无溢出(全部文字都在框内), 框尺寸不改` /
  `⚠ 段落文本溢出: 框高 38 → 114px (官方 boxOverflow, 试探 7 次, 3 行), …`。

### 验收

`node test_DialogueText.js` → **450 通过 / 0 失败**；`verify.py` / `install.py` 通过；
⚠️ **待真机验证**：49 字长句应完整逐字演满 6 秒；
日志「试探 N 次」应为个位数到十几（倍增 + 二分），不是一路撑到上限。

## v0.11.6 (2026-11-25) —— 修复段落文本溢出(出现时长像没生效、长句后半段看不到)

### 现象

v0.11.5 应用成功、日志也对（49 字、出现 6s、动画器 50、结束于 6.80s、无报错），
但实际效果「时长不对，似乎 6 秒不起效果」：肉眼只看到前一小段字在逐个出现，
大约 2 秒左右就停了，后面 4 秒什么都没有。

### 原因（已用 Adobe 官方文档交叉验证）

文本层是**段落文本（框文本）**：`文字 566x38px` —— 566px 宽、38px 高只有**一行**；
而 49 字在约 30px 字号下需要 3 行。Adobe 官方《创建和编辑文本图层》明确：
**段落文本超出定界框的部分不会显示**，定界框上只出现溢出图标。

于是：

- 时间轴完全正确：49 字的关键帧确实铺满 0 → 6.00s，隐藏阶段 6.00 → 6.80s；
- 但第 19~49 字整段落在定界框之外，**从头到尾都不可见**；
- 可见的约 18 字在 2.2s 就演完了，剩下 3.8s 在演「看不见的字」——
  于是看起来就是「6 秒没生效、时长也不对」。
- v0.11.4 的「长文本尾部不逐字出现」也是同一根因（当时误判为羽化右移）。

### 变更

- `getTextInfo` 采集段落文本信息：`doc.boxText` / `doc.boxTextSize` / `doc.leading`。
- 新增 `fitParagraphBox`：应用前把段落定界框**临时撑高**再测文字高度 ——
  - 文字高度变大 ⇒ 确有被裁掉的行：把框高收到**刚好容纳全部文字**（宽度不变，
    换行位置不变，只放出原本被裁的行），随后按新范围重新测量并建窗口蒙版；
  - 没变 ⇒ 没有溢出，原样还原，完全不改用户图层；
  - 源文本有关键帧/表达式时不写 TextDocument（避免覆盖动画），只写诊断；
  - 任何失败都还原原框高，只写诊断，不阻断应用。
- 应用日志新增：`点文本 / 段落文本(框 WxH)`、字号、行距、入/出点、
  ⚠ 时间拉伸 / ⚠ 时间重映射开启、以及溢出修复结果。
- `applyTypewriter` 写完后**读回关键帧**并打印：
  `关键帧核对: 首字起 0.00s / 末字 5.88s → 6.80s (期望 6.80s, 3 个关键帧)`；
  落点偏差超过半帧会加 ⚠ —— 万一宿主对关键帧时间做了换算，一眼能看出来。
- 新增纯函数 `isBoxOverflow(boxHeight, probedTextHeight)` / `fitBoxHeight(textHeight)`。

## v0.11.5 (2026-11-25) —— 逐字出现羽化改为向框外(修复长文本尾字不逐字出现)

### 现象

v0.11.4 应用成功（长句 49 字、出现 8s、动画器 50、无报错），但**文字特别长时，
并不是所有文字都逐字出现**：句子尾部的几个字没有按节奏逐个出现，
要等隐藏阶段整行左移时才露出来（甚至只在渐隐过程中闪一下就没了）。

### 原因

逐字出现的窗口 = 文本框，而蒙版羽化是**向内**扩散的：
清晰区比文本框左右各窄一个羽化宽（默认 25px）。
为让第一个字避开羽化，位置表达式把整行**向右移一个羽化宽**（`shift = cl - rl`）：

- 框 = 文字（零边距）时，右移 25px 就把**文字右缘推出框右缘 25px**；
- 尾部这一段的字整段落在羽化区/框外 —— 它们的出现关键帧照常执行，但看不见；
- 只有进入隐藏阶段、整行向左推 100px 时，尾部才被「滑」进窗口（此时整行正在渐隐）。

短文本（18 字、平均字宽 31px）只影响不到 1 个字，几乎看不出来；
长文本（49 字、平均字宽 11.5px）会吃掉尾部 2~4 个字，越到后面越明显。

### 变更

- 逐字出现的蒙版羽化改为**向框外**扩散（`computeFeatherOutsetBox`：路径左右各外扩半个羽化）：
  框内始终完全清晰，首尾的字从出现那一刻起就不发虚，**不再需要把文字右移**；
  横向滚动仍保持向内羽化（框外完全不可见）。
- 位置表达式重写（`buildTypeScrollExpression` 去掉 `featherX` 参数）：
  - 前沿按**文本框边界**算：`dx = br - (rl + avg * ks)`，上限 0（文字不右移）；
  - 下限 `dxEnd = min(0, br - rr)`：零/正边距时恒为 0 —— 出现阶段文字**完全不动**，

## v0.5.0 (2026-11-25) —— 新增开头 / 结束动态曲线

滚动不再只有匀速：面板新增「开头曲线」「结束曲线」两个下拉，只改**速度分布**，
起止点、时长、文本框、羽化都不变。

### 改动

- **开头曲线**：`匀速起步` / `慢起加速` / `快起减速`（默认 `匀速起步`）。
- **结束曲线**：`匀速收尾` / `减速慢收` / `加速快收`（默认 `匀速收尾`）。
- 新增纯函数 `easeProgress(k, startCurve, endCurve)`：先按进度算出「开头曲线 a」与
  「结束曲线 b」，再按 `q = a*(1-k) + b*k` 加权，端点严格 0 / 1。

  - 快起 + 慢收 = **前面快后面慢**（等价 `2k-k²`）；
  - 慢起 + 快收 = **前面慢后面快**（等价 `k²`）；
  - 匀速 + 匀速 = `k`（与 v0.4.0 行为完全一致）。
- `buildScrollExpression` 增加 `startCurve` / `endCurve` 参数，曲线在表达式里**内联展开**
  （不定义函数）：`var a = k; … var b = k; … var q = a*(1-k)+b*k; var dx = s+(e-s)*q;`。
- UI「动画」分组在「时长」下新增一行两个下拉；逐字出现模式自动禁用（无位移，曲线无意义）；
  「重置参数」恢复默认；应用日志打印两种曲线的文案。
