## 继承自模板的坑（不是本面板踩的，是骨架已经替你挡掉的）

这些坑都来自 MountainSpectrum 的真实事故。骨架里的写法看着冗余，**每一条都对应下面一次事故** ——
`test_DialogueText.js` 的骨架断言专门守着它们，删掉会直接变红。

### 坑 A：AE 报「在行 N 无法执行脚本」，而那一行是干净代码

**现象**：AE 弹「在行 2069 无法执行脚本。应为:」，同一症状在早期版本报的是「行 1871」。

**根因**：**AE 没重启**。ScriptUI Panel 由 AE **启动时**载入；磁盘文件后来被覆盖，内存里仍是旧版，
于是它报的是**旧文件**的行号，与磁盘上的代码无关（实测：AE 比脚本早启动 33 分钟）。

**修法**：① 先证伪"当前文件有 bug"（`node --check` + 不可见字符扫描）
② 比对 **AE 进程启动时间 vs 脚本 mtime**，前者更早就是没重启
③ **把版本号做进面板 UI** —— 打开面板即可判断 AE 里跑的是哪一版
④ 让用户**完全退出 AE** 再开（关面板 / 关工程都无效）

### 坑 B：给控件设了 `preferredSize` 高度却不生效

**现象**：「调试输出区」明明写了 `preferredSize = [320, 110]`，内容一多面板照样被撑高。

**根因**：紧随其后的 `pinW()` 内部有 `ctrl.preferredSize = [w, -1]`（**-1 = 高度自适应**）——
**在它之前设的高度被静默覆盖**。没有任何报错，只是"看起来没生效"。

**修法**：**先 `pinW` 钉宽度，再单独钉高度**（v0.2.0 抽成 `fixedBox`）。

**验证**：源码级**顺序体检**断言 —— `pinW` 的位置下标必须小于 `box.preferredSize = [w, h]`。

### 坑 C：`pinW` 只写 `preferredSize` 不够

**现象**：控件宽度钉了又被改回来，面板"弹宽"。

**根因**：`preferredSize` 是 ScriptUI 的 **volatile 属性，首次布局即丢失**
（Adobe 官方社区 Marc Autret 采纳答案：需要改用 `minimumSize`）。

**修法**：`preferredSize` / `minimumSize` / `maximumSize` **三处都写**；高度一律 `-1`，
**绝不**读回旧高度（刚建控件时可能是 0）。

### 坑 D：同一套数学写两遍（纯函数 vs 表达式）会分叉

**现象**：非法枚举值时，画面与状态栏数字对不上。

**根因**：纯函数用精确匹配，表达式用阈值分段，边界上必然分叉。

**修法**：两侧统一「先归一化再夹到合法范围，越界回退默认值」。

**验证**：`buildScrollExpression` 与 `computeScrollOffsets` 的**边界等价性断言** ——
测试从表达式里取回烘入的 `rl/rr` 与方向公式，和纯函数逐值比对。

### 坑 E：`scrollable` 这类控件属性在 AE 宿主里可能不被支持

**现象**：`colorpicker` 在 ScriptUI **Panels** 宿主里直接报
`UI element type ... is unknown or invalid in this context`。

**修法**：对"较新/较冷门"的控件属性做**存在性回退**（`try` 新建带属性的、失败了退化成基础形态），
**绝不让面板整个打不开**。`addNote` / `addTextBox` 的 `scrolling` 就是这么处理的。

### 坑 F：AE 的 handler 抛错是静默的

**现象**：点按钮什么也没发生 —— 没有报错、没有日志。

**修法**：所有 handler 经 `safeRun()` 包裹 + 诊断三件套（`diag` 收集 / 调试区显示 / 复制按钮）。

## 本面板自己的坑

### 决策 0T（v0.11.11）：选区索引与节奏改用非空白字符序号

**现象（v0.11.10 真机）**：44 字长句（含 1 个空格）动画器 44 个、无任何报错，
但**第一个「朵」（空格后第一个字）从 0 秒起一直显示**，隐藏阶段也不消失。

**根因（真机实证）**：脚本跳过空格不建动画器，但选区值与关键帧时间仍按**原文下标** `i` 排。
AE 26 真机显示：**索引单位下空格不占索引** —— 于是 AE 索引 31（第一个「朵」）
没有任何动画器覆盖；后续字整体早一拍，最后一个「?」由原来的 `i=42` 顶上。
官方帮助说「依据=字符」会数空格，与真机索引单位的行为不一致：
**以真机为准**，不依赖枚举含义（也不切换到未验证的 Based On=2）。

**修法**：

1. 新增纯函数 `countVisibleChars(str)`（`splitChars` + `/^\s$/` 过滤）并导出；
2. `applyTypeScroll`：`visN = countVisibleChars(...)` 驱动
   `computeTypeScrollTiming` / `buildTypeScrollExpression`，并传给 `applyTypewriter`；
   `visN` 为 0 时退回原始字数；
3. `applyTypewriter(..., visibleCount)` 循环递增 `selIdx`（遇到空白 `continue`，不加）：
   选区 `Index Start/End = selIdx / selIdx+1`、关键帧 `selIdx × step`、
   动画器命名 `DT_渐隐NN` 与百分比回退都用 `selIdx` / `visN`。

**验证**：`node test_DialogueText.js` → **506 通过 / 0 失败**；
✅ 真机确认（2026-11-25）：第一个「朵」按节奏出现、无字常显、`DT_渐隐32` 存在。
⚠️ 仍保留的架构风险：逐字方案依赖「每字一个选区」枚举 AE 索引；
换 AE 版本或特殊空白字符（全角空格 / 制表 / 换行）时需重新真机核对；
彻底的替代方案是单动画器 + Expression Selector（按时间算不透明度），暂不引入。

### 决策 0S（v0.11.10）：每个动画器逐个切索引单位，并写 Index Start/End

**现象（v0.11.9 真机）**：
`第 1 字: 设置选区失败: Error: … 无法将“set value” 与此属性一起使用，因为属性或父级属性被隐藏。`；
随后只有 43 个动画器（44 字 / 1 个空格 / 1 个失败）。

**根因（官方 matchName 表 + 真机）**：

1. 每个新建动画器都自带一个**默认选区**，默认单位是百分比；
   v0.11.9 只在第一个字切索引，后续动画器仍按百分比解释 `i / i+1` —— 选区几乎不覆盖任何字；
2. 切到索引后，Start / End 换成 **`ADBE Text Index Start` / `ADBE Text Index End`**；
   百分比那对此时是**隐藏属性**，写它会报「属性或父级属性被隐藏」；
   两对属性显示名都叫 Start / End，不能用显示名兜底。

**修法**：

1. `setSelectorUnits(sel, unitValue)`：只负责写 `ADBE Text Range Units`；
2. `setSelectorIndexMode(sel)`：切 `Units=2` → 确认 `Index Start/End` 存在 → 设 `Based On=Characters`；
   取不到索引属性就切回 `Units=1` 并返回 false；
3. `findSelectorStartEnd(sel, wantIndex)`：索引分支只取 Index 那对，百分比分支只取 Percent 那对，
   去掉原来的「百分比找不到就用索引」兜底；
4. `applyTypewriter` 循环内**每个动画器**调用 `setSelectorIndexMode`，按结果取属性、
   写 `i / i+1` 或百分比。

**验证**：`node test_DialogueText.js` → **491 通过 / 0 失败**；
⚠️ 待真机：无「设置选区失败」、每个 `DT_渐隐NN` 的 Units 都是 Index。

> ⚠️ 索引单位下空格**不占索引**，选区与节奏必须用可见字符序号 —— 见决策 0T（v0.11.11）。

### 决策 0R（v0.11.9，已撤回）：逐字选区用索引单位，百分比会把相邻字并进来

> ⚠️ v0.11.9 的实现已撤回（只切了第一个动画器 + 切完仍写百分比 Start/End），
> 修正见决策 0S；下面保留当时的现象与判断过程。

**现象**：段落文本（44 / 46 字）逐字出现时，**有两个字从 0 秒起一直显示**，
不按自己的时间淡入、隐藏阶段也不消失；日志正常（无溢出、动画器数量正确）。

**根因**：每字动画器的范围选择器用**百分比** `Start = i/n*100`、`End = (i+1)/n*100`。
字符数不能整除 100 时字符边界落在小数上，AE 按字符边界取整，
会把相邻字一起并进同一个动画器；被并进来的字沿用第一个动画器的关键帧
（0 → 100 后一直 100 到隐藏阶段），于是从 0 秒起就一直可见。

**修法**：

1. 新增 `setSelectorIndexMode(sel)`：`Units = Index(2)`、`Based On = Characters(1)`；
   官方《Animating text》写明单位可选百分比或索引，依据选字符时空格也计入索引；
2. 每字选区写 `Start = i / End = i + 1`（0 基）；社区通行做法
   `Units=Index + Start=0 / End=1` 就是第一个字（Adobe 社区 bounce 帖）；
3. 只在第一个非空白字探测一次；索引不可用才退回百分比，并写诊断
   `选区无法切换索引单位, 退回百分比(可能出现相邻字同时显示)`；
4. `Smoothness` 仍为 0；空格跳过不建动画器，但仍占索引，后续字不偏移。

**验证**：`node test_DialogueText.js` → **485 通过 / 0 失败**；
⚠️ 待真机确认：长句不再有字常显、范围选择器高级里 Units = Index、Start / End 相邻整数。

### 决策 0Q（v0.11.8）：段落文本「单行化 + 你的框就是出现窗口」

**现象**：v0.11.7 把溢出的段落框从 49 拉高到 129px，49 字全显示了，
但用户明确反对：**「原本的文本框被修改了……我给的文本框就是出现字的范围」**，
并要求：**文字不超出框，仍从右往左出现，像程序（终端）一样**。

**硬约束（官方交叉验证）**：

- Adobe Help《创建和编辑文本图层》：段落文本**按框宽自动换行**，拖动定界框手柄只会让文字**重排**；
  超出定界框的行**不渲染**（框上只出现溢出图标）；
- `TextDocument.boxText` **只读**：脚本不能把段落文本转成点文本（官方只提供右键菜单互转，
  且转点文本会删除框外字符）；
- ⇒ 595px 宽 + 49 字 + 字号 40.6 必然排 3 行，「框保持 49 高」与「3 行全可见」**不能同时成立**；
  要整句一行，**排版框宽度必须够**。这是 AE 的硬规则，不是实现取舍。

**修法**（`fitParagraphBox` 重写，v0.11.7 的「拉高框」全部删除）：

1. 框高设成**一行高**：`layoutH = max(原框高, ceil(行距))`（行距缺失按字号 × 1.2）；
   此时 `boxOverflow === false` 等价于「整段排成一行」——高只够一行，多一行就溢出；
2. 宽度**倍增**（`w→2w→4w…`，上限 `max(8192, 32w)`）找到第一个不溢出，再**二分**到最小一行宽；
3. 写回 `boxTextSize = [一行宽, 一行高]`，**复核 `boxOverflow`**，失败一律 `restore()` 还原原框；
   成功后 `restoreBoxPos` 复位 `boxTextPos`；
4. **窗口 = 用户原框**：`boxTextSize` + `boxTextPos`（层坐标，与 `sourceRectAtTime` 同坐标系），
   宽高**都不动**；点文本仍沿用文字外框；
5. 原框尺寸写进蒙版名 `DT_窗口 595x49`：排版框已被加宽，**重复应用**必须能找回真正的窗口；
   `isOurMaskName` 改为前缀判定（`DT_窗口` / `DT_窗口 595x49` 都算），旧蒙版照常清理；
6. 窗口比文字窄时，位置表达式 `dx = br - (rl + avg*ks)`（上限 0）自动「打满后整行左移」，
   即终端式从右往左流动；零/正边距的老行为不受影响；
7. 框高小于一行（框高 < 行距）→ 日志告警（文字上下会被窗口裁掉）；
   文本含强制换行（`\r`）→ 宽度加满仍溢出 ⇒ 还原 + 告警，不硬改。

**为什么不用「新建点文本层」**：会多一个图层、破坏「就地」约束，且文字后续修改不会同步；
**为什么不用 `boxAutoFitPolicy`**：它把自动撑高持久写进用户的文本属性。

**验证**：`node test_DialogueText.js` → **474 通过 / 0 失败**（新增 v0.11.8 二十条断言）；
⚠️ 待真机确认（先 Ctrl+Z 撤销 v0.11.7 的撑高，回到 595x49 再应用）。

### 决策 0P（v0.11.7）：段落框溢出用官方 boxOverflow 判定，倍增 + 二分定框高

**背景**：v0.11.6 的探测法依赖 `sourceRectAtTime(t, false)` 在撑高后返回**文字范围**。
官方表达式参考只说明 `includeExtents=true` 时段落文本返回**段落框边界**，
没有保证 `false` 的情形；若宿主返回框尺寸，探测法只能还原 + 告警，溢出仍在。

**官方依据**（ae-scripting.docsforadobe.dev / TextDocument，AE 24.6+，本项目 AE 26.0 可用）：
- `TextDocument.boxOverflow`（只读布尔）：有文字没能排进定界框时为 `true`；
- `TextDocument.boxTextSize`：`[宽, 高]` 可读写（整数，最小 1）；
- `TextDocument.boxTextPos`：框左上角图层坐标，可读写；
- `TextDocument.composedLineCount`：排进框里的行数（全溢出时可能为 0）；
- TextDocument 实例是**组合时快照**：改它不会重排，必须 `setValue` 后重新取 `st.value`。

**修法**：
1. 读 `st.value.boxOverflow`（新取的对象）：
   - `false` ⇒ 全部文字在框内，**不动用户的框**（常见情况零改动）；
   - `null` ⇒ 旧版 AE 没有该属性，退回 v0.11.6 探测法；
   - `true` ⇒ 进入 2。
2. 倍增：`h → 2h → 4h …`（上限 `max(4096, 64h)`，最多 16 次）找到第一个
   `boxOverflow === false` 的高度。
3. 二分：在「已知溢出 lo」与「已知不溢出 hi」之间收敛到最小可容纳高度（整数）。
4. 写回 `boxTextSize = [原宽, hi]`（宽度不变 ⇒ 换行不变），
   **再读一次 `boxOverflow` 复核**；仍为 `true` 或任何异常 ⇒ 还原原框高。
5. 成功时 `restoreBoxPos` 把 `boxTextPos` 写回原值：
   AE 若以中心为基准缩放框，文字会跟着跳；恢复框位置保证文字留在原处。
6. 日志打印 `⚠ 段落文本溢出: 框高 38 → Npx (官方 boxOverflow, 试探 N 次, M 行)`；
   无溢出打印 `段落框无溢出(全部文字都在框内), 框尺寸不改`。

**为什么不用 `boxAutoFitPolicy`**：它会把「自动撑高」持久写进用户的文本属性，
之后用户手动改框也会被宿主拉回去；本面板只借宿主的判定，不改用户的排版习惯。

**验证**：`node test_DialogueText.js` → 450 通过 / 0 失败（新增 v0.11.7 十四条断言）；
⚠️ 待真机确认（49 字长句演满出现时长，日志「试探 N 次」应为个位数到十几）。

### 决策 0O（v0.11.6）：先修段落文本框高，再谈「出现时长」

**现象**：v0.11.5 日志完全正常（49 字、文字 566x38px、出现 6s、动画器 50、结束 6.80s、
无报错），用户却说「不对，时长也不对，似乎 6 秒不起效果」：肉眼只看到前一小段字
逐个出现，约 2 秒就停了。

**根因（不在时间轴）**：`566x38px` 说明文字块只有**一行高**；49 字在约 30px 字号下
需要 3 行。文本层是**段落文本（框文本）**，Adobe 官方《创建和编辑文本图层》写明：
**段落文本超出定界框的部分不会显示**（框上只出现溢出图标）。
所以：

- 关键帧确实铺满 0 → 6.00s（`step = (6-0.12)/48 = 0.1225`），隐藏 6.00 → 6.80s；
- 但第 19 字之后整段落在框外，**从头到尾不可见**；
- 可见的约 18 字在 `17×0.1225 + 0.12 ≈ 2.2s` 演完，剩下 3.8 秒在演看不见的字；
- 于是用户看到「2 秒演完 + 时长不对」，并把 v0.11.4 的「尾字不出现」也归到同一处。

**判定**：`sourceRectAtTime(t, false)` 是**文字边界**，`includeExtents=true` 才是
段落框范围（官方表达式参考）；但被裁掉的文字不会进入边界 —— 光靠测量分不清
「只有一行」还是「框只有一行高」。所以用**探测法**：临时把框撑高再测，
文字高度变大就证明原来有被裁的行。

**修法**：
- `getTextInfo` 采集 `doc.boxText / boxTextSize / leading`；
- 新增 `fitParagraphBox(layer, st, doc, compTime)`：
  1. 只处理 `doc.boxText === true`；
  2. 源文本有 `numKeys`/`expressionEnabled` → 不写 doc（会覆盖动画），只写诊断；
  3. `probeH = max(2000, 框高×40)`，撑高后测量：`ph >= probeH - 2` 说明该版本
     返回的是框尺寸 → 还原并告警；`isBoxOverflow(原框高, ph)` 为真 →
     `boxTextSize = [宽, fitBoxHeight(ph)]`（宽度不变 ⇒ 换行不变，只放出被裁的行）；
  4. 任何失败都 `setBox(原框高)` 还原，绝不把用户的框留在撑高状态；
  5. 每次写框都重新 `st.value` 取 TextDocument，不复用旧对象。
- `doApply` 第一遍在 `getTextInfo` 之后调用它，并用重新测量到的范围建窗口。
- 日志新增：`点文本 / 段落文本(框 WxH)`、字号、行距、入/出点、⚠拉伸、⚠时间重映射，
  以及 `⚠ 段落文本溢出: 框高 38 → Npx`。
- `applyTypewriter` 写完后读回 `keyTime()`，打印
  `关键帧核对: 首字起 … / 末字 … → … (期望 …)`，偏差超过半帧加 ⚠ ——
  若宿主对关键帧时间做了换算（拉伸/重映射），一眼可见。

**验证**：`node test_DialogueText.js` → 436 通过 / 0 失败（新增 v0.11.6 三十条断言）；
⚠️ 待真机确认（长句应完整逐字演满 6 秒，日志出现框高修复与关键帧核对）。

### 决策 0N（v0.11.5）：逐字出现的羽化必须向框外，位置表达式不能右移文字

**现象**：v0.11.4 应用成功（长句 49 字、出现 8s、动画器 50、无报错），
但**文字很长时不是所有字都逐字出现**：句子尾部的几个字要等隐藏阶段整行左移才露出来，
甚至只在渐隐过程中闪一下。

**根因（几何必然）**：逐字出现的窗口 = 文本框（零边距时框宽 = 文字宽），
而蒙版羽化是**向内**的（`computeFeatherInsetBox`：路径各内缩半个羽化），
清晰区比框左右各窄一个羽化宽（默认 25px）。
为让第一个字避开羽化，位置表达式把整行**右移一个羽化宽**（`shift = cl - rl`）：

- 框 = 文字时，右移 25px 就把**文字右缘推出框右缘 25px**；
- 尾部这一段的字整段落在羽化区/框外 —— 它们的不透明度关键帧照常执行，但**看不见**；
- 只有进入隐藏阶段、整行再向左推 100px 时，尾部才被「滑」进窗口（此时整行正在渐隐）。

短文本（18 字、平均字宽 31px）只影响不到 1 个字，几乎看不出来；
长文本（49 字、平均字宽 11.5px）会吃掉尾部 2~4 个字，越到后面越明显。

**修法**：
- 新增 `computeFeatherOutsetBox(box, featherX)`：路径左右各**外扩**半个羽化。
  逐字出现时 `applyWindowMask(..., outward=true)` 用它 → 框内完全清晰、过渡区全在框外，
  **不需要再把文字右移**；横向滚动仍用 `computeFeatherInsetBox`（框外完全不可见）。
- `buildTypeScrollExpression` 去掉 `featherX` 参数，后半段重写：
  - `dx = br - (rl + avg*ks)`（前沿按框右缘算），上限 **0**（文字绝不右移）；
  - 下限 `dxEnd = min(0, br - rr)`：零/正边距时恒为 0 → 出现阶段文字**完全不动**；
    只有负边距（框比文字窄）时前沿到框右缘后整行才左移；
  - 隐藏阶段从 `dx0 = dxEnd` 连续出发（不在 `t = 出现时长` 处跳），再向左推隐藏像素。
- 应用日志补 `文字 WxHpx`，便于核对长文本的测量结果。

**为什么不采用「通篇连续左移」**：那是另一种打字机（纸在动），
与用户要的「框内逐字出现、打满后才左移」不一致；本次只去掉造成裁切的右移。

**验证**：`node test_DialogueText.js` → 405 通过 / 0 失败（新增 v0.11.5 二十条断言）；
⚠️ 待真机确认（长句应从第一个字到最后一个字完整逐字出现）。

### 决策 0M（v0.11.4）：整体渐隐必须写进每字动画器，不能挂在覆盖全行的动画器上

- `applyTypewriter` 增加 `hideStart / hideEnd`：每个字**自己的**不透明度动画器在

### 决策 0H（v0.10.0）：逐字出现加羽化补偿，新增「隐藏像素」

**现象（用户反馈）**：「羽化是内向羽化，所以一开始文字边缘就会发虚了。需要在逐字出现的
方案中，文字会自动移动相应的像素，让文字不会被羽化。然后增加一个参数隐藏像素，
可以控制在隐藏时间内，向左位移的距离。」

**根因**：蒙版路径左右各内缩 `fe/2`，羽化再向两侧各扩散 `fe/2`，
所以蒙版不透明度 100% 的清晰区是 `[框左+fe, 框右-fe]`，比文本框左右各窄一个羽化宽。
零边距时文字左缘正好落在框左（不透明度 0），第一个字当然发虚。

**修法**：
- 表达式里显式算清晰区 `cl = bl + fe`、`cr = br - fe`；
- 初始右移 `shift = cl - rl`（夹 ≥0、且不超过 `cr - rl`），文字左缘自动进入清晰区；
- 打字前沿 `ks = t / step + 1`（把正在画的字宽也算进去，夹 0..n）；
  `dx = cr - (rl + avg*ks)`，超过 `shift` 就取 `shift`，
  所以新出现的字连同右缘都落在清晰区里，不会一头扎进羽化边；
- `fe` 在纯函数里夹到半框宽，避免清晰区反向；应用到层空间时按图层缩放反算。
- 新增 `隐藏像素`：隐藏阶段 `dx1 = dx0 - hpx`，hpx = 面板像素 / 图层缩放；
  0 = 停在出现结束位置；足够大 = 完全滑出（旧行为需要手填约「文字宽 + 羽化」）。
- 抽出 `getScaleXY(layer)`，`applyWindowMask` 与 `applyTypeScroll` 共用，避免两份缩放读取。

**为什么滚动模式不补偿**：滚动的设计就是文字从羽化边穿进穿出；
补偿会把整条轨迹往框内挤，反而破坏"从边缘渐显"的效果。

**验证**：测试新增 `fe/cl/cr/shift`、隐藏像素、半框夹取、负值归零等断言。

### 决策 0E（v0.7.0，已并入 v0.8.0）：逐字左移 = 一整套动画（窗口=文本框，出现 + 滑出两段）

**现象（用户反馈）**：「理解错了，逐字出现，然后隐藏是一整套动画，而且也需要时间可以控制的。」

**根因**：v0.6.0 把「窗口宽」做成必须手填的参数（0 = 永不左移），
又把结尾做成「停留 + 整体渐隐」。用户的预期是：
- 显示窗口就用**文本框**，不需要再算一个宽度；
- 只要两个时间：**出现总时长** + **隐藏时长**；
- 隐藏不是渐隐，而是**整行继续向左滑出窗口**。

**修法**：
- 删除 `窗口宽` / `停留` / `整体渐隐`，删除 `computeTypeScrollBox` 与 `DT_渐隐整体`。
- 窗口 = `computeBox`（文字范围 + 四边边距），与横向滚动完全一致。
- `computeTypeScrollTiming(n, appearDur, fade, hideDur)`：
  `step = (appearDur - fade) / (n - 1)`（单字为 0），`lastVisible = appearDur`，
  `endTime = appearDur + hideDur`。每字关键帧从 `i*step` 到 `i*step + fade`。
- `buildTypeScrollExpression(n, rl, rw, bl, br, appearDur, fade, hideDur, is3D)` 分两段：
  - 出现：`ks = t / step` 夹 0..n，`dx = br - (rl + avg*ks)`，只在 `dx > 0` 时归零；
  - 隐藏：`t > appearDur` 后 `h = (t - appearDur) / hideDur`，
    `dx = dx0 + (dx1 - dx0) * h`，其中 `dx0` = 出现结束时的位移（≤0），
    `dx1 = bl - rr`（文字右缘贴窗口左缘 = 完全滑出）。
  两段在 `t = appearDur` 处连续，`dx0` 也做 ≤0 夹取，窗口比文字宽时不会跳。
- `applyTypewriter` 增加可选 `intervalOverride`：逐字左移传 `timing.step`，
  逐字出现仍用 `1 / 字速`，两条路径共用同一套每字动画器。
- 出点延长到 `endTime`。

**几何必然**：零边距时窗口宽 = 文字宽，打字前沿最多走到窗口右缘（`dx` 最小 0），
所以**打字阶段不会左移**，只有结尾整行滑出。想看中途左移必须把右边距填负数收窄窗口 ——
这是「窗口=文本框」的直接推论，不要为了"看起来在动"加虚假位移。

**验证**：`computeTypeScrollTiming` 步长/末字时刻/结束时刻/非法值回退；
表达式两段的关键行与连续性；UI 断言（有出现/隐藏、无窗口宽/停留/整体渐隐）；
`applyTypeScroll` 不再引用 `ANIM_FADE_PREFIX`；`doApply` 统一 `computeBox`。

### 决策 0D（v0.6.0，**已被 v0.7.0 取代**）：新增「逐字左移」——固定窗口逐字出现 + 满窗整体左移 + 结尾整体渐隐

**需求（用户原话）**：「文字从左侧一个一个出现，到右侧，如果还有文字，就整体向左移动，
到最后一个字出现，然后整体一段时间渐隐。需要增加一些参数控制。」

**关键判断**：
- 这是「逐字出现」的变体，但它**必须有一个固定窗口**：不设窗口宽时，文字框始终等于文字宽，
  永远"装得下"，不会发生左移。因此新增参数 `窗口宽(px)`，窗口右边 = 框左边 + 窗口宽。
- 左移量不能用「每字关键帧」算（字符宽度不一），改用**平均字宽模型**：
  `avg = 文字宽 / 字数`，打字前沿 `front = 文字左缘 + avg × 已出现字数`；
  `dx = 窗口右缘 - front`，只在 `dx < 0` 时生效（即满窗才开始推）。
  这样位移是连续函数，不会随字符宽度跳变。
- 整体渐隐不能复用每字符的 `DT_渐隐*` 动画器（那些按字符分段）；
  另建 `DT_渐隐整体` 的 Opacity 动画器，100 → 0 两个关键帧，
  **它与逐字动画器的透明度相乘**，最后一个字出现后才开始淡出，视觉上是整块淡出。
- 时间轴由纯函数 `computeTypeScrollTiming(n, cps, fade, hold, fadeOut)` 统一给出：
  `lastVisible = (n-1)/cps + fade`，`fadeStart = lastVisible + hold`，`fadeEnd = fadeStart + fadeOut`；
  出点自动延长到 `fadeEnd`。

**为什么不用蒙版做整体渐隐**：蒙版不透明度只有一个静态值，做渐隐要打关键帧，
而且与已有羽化/强度语义混在一起；Opacity 动画器更干净，也不动蒙版参数。

**退化行为**：`窗口宽 = 0` 时窗口跟随文字，位移恒为 0，效果等于「逐字出现 + 整体渐隐」。

**验证**：窗口框几何（跟随 / 固定 / 右边界）、表达式（满窗前 `dx=0`、满窗后负值、
3D 返回 `[dx,0,0]`）、时间轴（末字时刻 + 停留 + 淡出）、UI 接线（仅该模式启用三个新参数）。

### 决策 0C（v0.6.0）：首次加载慢 + 说明文字白底滚动条

**现象（用户反馈）**：「第一次加载很久，UI 上有很多白色的滑动条；字速、文本框这些说明文字
不需要用输入框」。

**根因**：
- 加载慢：`flog()` **每写一条就整文件重写一次**桌面日志，桌面被网盘同步时每次写入几十~几百 ms；
  面板挂载期间几十条日志累计成秒级等待。
- 白框/滚动条：说明文字用了只读 `edittext`，AE 里它是白底，内容超出高度就出现滚动条。

**修法**：
- 日志改**内存累积 + 节流落盘**：`gLogLines`（上限 2000 行），最多每 `LOG_WRITE_GAP=800ms`
  整文件写一次；`flushLog()` 在挂载结束 / handler 成功 / 异常 / 兜底界面时强制写。
  首次加载从"每条一次写"降到"一次写"。
- `addNote` 改用 `statictext`（自动换行、无边框），只有底部「输出与调试」保留一个多行框供复制日志。
- **真实数值参数仍是输入框**（字速 / 时长 / 边距 / 羽化 / 窗口宽等），只有说明文字改成纯文本。

**验证**：`flog` 不含直接 `f.open("w")`、`flushLog` 存在且挂载/safeRun 调用；
`addNote` 函数体断言用 `statictext` 且无 `edittext` / `fixedBox`。

### 决策 0B（v0.5.1）：羽化只向框内扩散，框外完全不可见

**现象（用户反馈）**：v0.5.0 框外还能看到半透明文字，用户要求「羽化是向内羽化，
所以超出边框会完全看不到」。

**根因**：AE 的**蒙版羽化以路径为中心向两侧扩散**（v0.2 的「决策 2」就记录过这一点）。
v0.4.0 起蒙版路径正好压在文本框边缘，于是羽化有一半落在框外 —— 框外 f/2 范围内
文字是半透明的，视觉上就是「超出边框还能看见」。

**修法**：
- 新增纯函数 `computeFeatherInsetBox(box, featherLayerX)`：左右路径各向内缩 `f/2`，
  外扩的一半正好回到框边，过渡区全部落在框内；上下不羽化、不内缩。
- 羽化值先按 `scaleX` 反算成层空间，再夹到框宽以内；路径至少保留 0.5px，避免退化。
- `buildMaskVertices` 仍只接收矩形，传入内缩后的框；`fea.setValue([featherX, 0])`。

**验证**：`computeFeatherInsetBox` 的几何断言（内缩半个羽化、外边界与框边对齐、
极端大羽化不反向、负值归零）+ 源码断言（路径用内缩框、羽化只设左右）。

### 决策 0A（v0.5.0）：开头曲线 + 结束曲线，用加权组合覆盖三种常见手感

**需求**：滚动不能只有匀速；要在面板里选「开头的曲线」和「结束的曲线」，
至少覆盖淡入淡出、前面快后面慢、前面慢后面快。

**方案**：两个独立下拉 + 一个纯函数 `easeProgress(k, startCurve, endCurve)`：
- 开头曲线产出 `a`：匀速 `k` / 慢起 `k²` / 快起 `1-(1-k)²`；
- 结束曲线产出 `b`：匀速 `k` / 慢收 `1-(1-k)²` / 快收 `k²`；
- 组合 `q = a*(1-k) + b*k`，端点严格 0/1。

**为什么不用两段贝塞尔 / 单条曲线预设**：
- 两个下拉能正交表达「起步」和「收尾」，组合数 9 种，覆盖用户要的三种且不丢自由度；
- 加权式在 `k=0` 时只剩 `a`、`k=1` 时只剩 `b`，端点天然严格，不会跳变；
- 匀速 + 匀速退化为 `q=k`，与 v0.4.0 行为逐字一致 —— 老工程重应用不会改变效果。

**组合结果（已写入测试）**：
| 开头 | 结束 | 结果 |
|---|---|---|
| 慢起 `k²` | 慢收 `1-(1-k)²` | 淡入淡出（= smoothstep `3k²-2k³`） |
| 快起 `1-(1-k)²` | 慢收 | 前面快后面慢（= `2k-k²`） |
| 慢起 | 快收 `k²` | 前面慢后面快（= `k²`） |

**表达式**：曲线必须内联进表达式（AE 表达式里不定义函数更稳），
且**不改** `s / e / dur` 三行 —— 测试用前三行列比对，保证曲线只动速度分布。

**逐字模式禁用**：逐字没有位移，曲线无意义；`updateModeUI` 把两个下拉置灰，
但 `readParams` 仍会读取（值被忽略），避免切换模式时控件状态错乱。

### 决策 0（v0.4.0）：文本框改为贴合文字自身范围（v0.11.8 已修订，见决策 0Q）

**现象**：v0.3.0 按「画面四边内缩」建框。用户四个内缩都是 0 时，窗口=整个 5120×1600 画面，
文字（宽 557px）从画面右边缘一路横穿到左边缘 —— 反馈「整个文本框移动了」。

**根因**：窗口范围取自画面，与文字自身位置/大小无关；零内缩时窗口大到看不见边，
视觉上只剩整块文字在飞。

**方案**：
- `computeBox(rect, padL, padR, padT, padB)`：`rect` 取自 `sourceRectAtTime`（层空间），
  边距 0 = 紧贴文字，正数外扩，负数内收；逐层生成，多选时每层各自的框。
- 蒙版改**静态 Shape**（`new Shape()` + 顶点/零切线/闭合 + `setValue`），不再写路径表达式，
  也不再需要 `fromComp()`；框留在文字原位置，随图层缩放/旋转一起变换。
- 滚动起止点直接用框的左右边界（层空间常量），零边距时行程 = 2 倍文字宽。
- **羽化只作用左右**：框贴合文字后，上下羽化会把文字上下缘吃淡。
- **逐字模式不加蒙版**：文字不移动，蒙版只会啃掉文字边缘。

**取舍**：框在应用时按当时文字范围生成一次；之后再改文字内容/字号，需要重新应用。

### 决策 0½（v0.3.0，**已被 v0.4.0 取代**）：参数化文本框替代空对象控制器

> v0.4.0 已把窗口改成「贴合文字」；下面保留作为历史记录，说明窗口范围为什么一度按画面算。

**背景**：v0.2 用两个空对象实时控制左右消失点，用户反馈「复杂了」——
不想在合成里多出两个图层，也不想拖控制器，只想在面板里输参数。

**方案**：
- 上下左右四个**内缩值**（px，0 = 贴画面边）→ `computeBox()` 得到合成坐标矩形；
- **羽化距离**（px）→ 蒙版羽化；**羽化强度**（%）→ 蒙版不透明度（用户确认的语义）；
- 蒙版路径仍是表达式：四个角以合成坐标写死，运行时 `fromComp()` 换算到图层空间，
  因此缩放/旋转/父级图层上的框在画面上仍是轴对齐矩形；
- 滚动起止点改由文本框左右边界决定，表达式里 `fromComp([boxLeft, midY])`；
- 改参数后**再点一次「应用动画」**即重建（先按名称清理旧动画），不叠加。

**取舍**：牺牲了「拖动即实时改」的交互，换来零额外图层、参数集中、可重复调整。
**遗留**：文本框是整批共用一个；极端旋转时滚动起止点用上下中点近似。

### 决策 1（v0.2.0）：读取选中文本层，就地加动画

**背景**：旧方案（多行脚本 → 解析排期 → 新建字幕层）被用户否决 ——
用户要保留现有文字的**位置、字体、字号**。

**方案**：
- 只处理 `comp.selectedLayers` 里的文本层（`TextLayer` 或 matchName `ADBE Text Layer`）；
- 只读 `Source Text` 的 `text` / `fontSize` 用于测量与上限，**从不 `setValue` 回写**；
- 不改图层 `Position` / `Scale` / 源文本。

**代价**：非文本层会被跳过；多选时用文字范围并集估算控制器默认位置。
**收益**：与用户现有排版/样式零冲突。

### 决策 2（v0.2.0，**已被 v0.3.0 取代**）：1 个窗口蒙版 + 2 个空对象，路径/羽化全用表达式

> v0.3.0 已移除空对象；下面保留作为历史记录，说明「为什么曾经用表达式跟随控制器」。

**为什么不打关键帧**：用户要求拖动控制器时两端渐隐**实时**变化，关键帧做不到。

**为什么只用 1 个蒙版**：两个蒙版 Intersect 需要保证蒙版顺序与模式，且两层羽化会互相叠加；
1 个矩形 + 双侧羽化更稳定。

**坐标**：蒙版路径在图层空间；表达式里 `fromComp(控制器位置)[0]` 换算 x。

**羽化**：`[f, 0]` 只横向；窗口过窄时自动收窄到窗口宽，避免左右羽化互相吃掉。

**路径边缘**：`lo + f/2` / `hi - f/2` —— 羽化以路径为中心扩散，
让过渡区大致落在 `[lo, lo+f]` / `[hi-f, hi]`。

### 决策 3：滚动用文本动画器 Position 表达式，不动图层位置

- matchName 必须是 **`ADBE Text Position 3D`**（官方文本动画 matchName 列表）；
  用 `ADBE Text Position` 会报 `Can not add a property with name "ADBE Text Position"`。
- 表达式返回 `[dx, 0, 0]`（3D 属性必须三维），`dx` 由文本框左右边界与文字左右缘计算：
  - RTL：`s = hi - rl; e = lo - rr;`
  - LTR：`s = lo - rr; e = hi - rl;`
- v0.4.0 起 `lo/hi`（文本框边界）与 `rl/rr`（文字左右缘）都是**应用时烘入的层空间常量**，
  表达式里没有 `fromComp()`、不引用任何图层。

### 决策 4：逐字出现仍用每字符一个 Opacity 动画器

沿用 v0.1.x 的结论：Range Selector Smoothness 的首尾行为不确定，会出现首字预显 / 末字半透明。

- 每字符：selector `Start/End = i/n*100 → (i+1)/n*100`，Smoothness = 0，
  Opacity `0 → 100` 线性关键帧；
- 空白字符跳过动画器，但仍占用字符序号（与 AE 的字符索引一致）。

### 坑 5：先清理旧动画再测量，否则窗口会偏

**现象（推演 + 代码审查）**：重新应用时，`sourceRectAtTime` 会把旧滚动表达式的位移算进文字范围，
导致文本框与滚动起止点偏移，且每次重应用可能累积偏移。

**修法**：`doApply` 第一遍按图层 `clearOurAnimation` → `getTextInfo` 测量；
第二遍才建控制器和动画。

**验证**：源码顺序断言 + 真机重复应用两次对比。

### 坑 6：按名称清理（v0.2 → 现在）

- 动画器：`DT_滚动` / `DT_渐隐**`；蒙版：`DT_窗口`。
- 为什么不按索引：用户插入/删除图层会错位。
- v0.2 的控制器 `DT_左消失点` / `DT_右消失点` 已在 v0.3.0 移除，表达式不再引用任何图层名称。

### 坑 7：`tabbedpanel` / 分页（v0.1.0 → v0.1.2，仍有效）

**现象 1**：v0.1.0 真机打开面板，UI 完全没加载。
**原因**：`tabbedpanel` 在本仓库无先例，AE 的 ScriptUI Panel 宿主对它并不可靠；且没有兜底。

**现象 2**：v0.1.1 改为「下拉选页 + group 显隐」后能显示，但用户明确「面板就不应该分页」。

**修法（v0.1.2 定稿）**：单页纵向 + `panel` 分组，参数全部直接可见；
主按钮与状态栏固定在版本号下方。

**教训**：
- **ScriptUI 的构建错误是静默的** —— 面板空白时，面板内的诊断区也一起没了，
  所以「日志必须落在面板之外」。
- **不要为了省高度把参数藏进页签/下拉**。
- 任何新容器先做最小可用验证，再往里堆控件。

### 坑 8：少了 `layout.layout(true)`，日志全绿但面板整窗空白（v0.1.2 → v0.1.3，仍有效）

**现象**：v0.1.2 部署后真机打开，面板一个字都没有；桌面日志完整走完、没有 `!!` 异常。
不是控件没建出来，而是**建出来了没被排版**（尺寸全 0）。

**根因**：AE 的 ScriptUI Panel 不会自动给运行时动态添加的控件做布局。
v0.1.1 的分页函数里顺带调了 `pal.layout.layout(true)`；v0.1.2 删分页时把它一起删了。

**修法**：`mountPanel()` 的 Panel 分支末尾必须有 `pal.layout.layout(true)`，
并把 `pal.size` / `pal.preferredSize` 写日志 —— 区分「没排版」与「内容超高被裁切」。

**教训**：
- **重构删代码时，要检查被删函数里有没有「顺手做的必要副作用」**。
- **日志全绿 ≠ 界面正常**：日志只能证明代码路径走通，不能证明绘制成功。
- 面板脚本改动后必须**完全退出并重启 AE** 才载入新文件。

### 待真机验证（v0.4.0，历史存档；最新清单见 AGENTS.md）

1. 面板显示 `v0.4.0`、两个分组可见、顶部按钮可点；日志有 `布局完成` 且尺寸非 0。

  - 不用「源文本 substring 表达式」：居中/右对齐会随字数变化重排；文本动画器不改排版。
  - 段落在定界框外的行 AE 不渲染（官方《创建和编辑文本图层》）——
    v0.11.6 ~ v0.11.8 的溢出修复都建立在这一点上。

    AM Typewrite（光标 / 多行 / RTL）、Typeverb（方向 / 距离 / 单位 / 时序）、
    Texto（字母·词·行 / 弹簧 / 预设）。
