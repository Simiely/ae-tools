# 更新日志（CHANGELOG）

## v2.0.13（当前版本）

- **修复「句号被放到最左/行首，本应在最右」**：上一版放宽段框宽后仍复现 → 二字非换行、而是**文本方向（direction）**。根因 = **源图层继承了 RTL/双向文本方向**时，AE 的 bidi 引擎把文字**按从右到左重排**，本在句尾的句号「。」被排到句子最左端；中文场景下汉字为 LTR 强字符次序大体不变，唯句末标点被排到段首，视觉即"句号跑到最左"。佐证：Adobe 官方 `ParagraphDirection`（LTR/RTL）枚举、社区 AE「文本反向、问号/引号跑到 front 而不是 end」案例、Reverse-Text 这类专为"标点被 RTL 排错"的插件
- 修复：`applyLyricText` 写回时显式 `d.direction = ParagraphDirection.DIRECTION_LEFT_TO_RIGHT`（横向从左到右），排除源层 RTL 方向继承；兼容无方向属性版本（try/catch）。保留 v2.0.12 的框宽放宽（两条互补：一防换行、一防反向）
- 验证：全插件代码对字符顺序零改动（parseLyrics 仅 trim、measureFit 仅改字号、charCodeAt 仅估宽），已完整审计确认
- 测试 39 → **41**（用例 13：源层 RTL direction 被显式锁定为 LTR）

## v2.0.12

- **修复「句号被放到行首」**：歌词句末的中文句号「。」被排到句子开头。根因 = **源图层若是段落（有边框）文本框**，插件复用该样式写歌词后会被 AE 按框宽**自动换行**，中文闭标点（UAX#14）在断行时落到下一行行首；放大句字号大、更易触发。
- 修复：写入歌词一律走 `applyLyricText`，检测 `boxText` 为段落文本框时先把 `boxTextSize` 放宽到 `2×comp.width+200`，杜绝自动换行，标点始终留在句尾；达不成段落文本框则不影响（point text 正常路径）
- 依据：Adobe 官方文档「paragraph text box 中文本按边界框宽自动换行」「`boxText`/`boxTextSize` 用于段落文本框」
- 测试 37 → **39**（用例 12：段落文本框写回会自动放宽框宽、文本含句号正确写入）

## v2.0.11

- **修复左/右对齐下「放大句」不贴边**：真机发现选左对齐后放大句（当前句）仍偏位、未贴 30px，且较长放大句向右左漂移时"句号/末尾"被挤到行前。根因 = **对齐偏移按「未缩放宽度」计算**：锚点在文本中心，中心缩放不会让中心漂移、但会让左/右缘随 scale 移动；而 `sourceRectAtTime` 返回的是 scale=100% 的源宽，放大句照它套 left/right 边距必然偏位
- 修复：position 表达式内 `w = sourceRectAtTime(...).width × transform.scale[0]/100`（实时缩放感知）→ 放大句也能把指定边精确贴到 30px 边距；居中不受影响（ax=0，与缩放无关）
- 测试：mock 注入 `transform.scale` 支持；用例 10 新增放大句左/右、普通句左/右 + 居中不破坏，断言 35 → **37**

## v2.0.10

- 测试扩至 **35 项断言**（新增用例 11：`buildLyrics → buildController` 参数透传回归，左=0 / 右=2）
