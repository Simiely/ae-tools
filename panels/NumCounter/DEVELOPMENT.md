# DEVELOPMENT.md · 开发记录

## 一、项目概览

NumCounter 是 ae-tools 的新面板(2026-09-01 首发):一键生成「数字从起始值递增到目标值」的动画。定位 = 把仓库已有手工套路 `tips/ae/expressions.md`「数字计数器(滑块控制)」做成带 UI 的工具,并**补全数字宽度抖动修复**。动画由「数值」滑块关键帧 + sourceText 表达式驱动,生成后仍可拖滑块/关键帧调整。

## 二、架构说明

```
panels/NumCounter/
├─ NumCounter.jsx        主面板(ES3, 单文件)
├─ test_NumCounter.js    纯逻辑层 node 断言(19 项)
├─ README/AGENTS/CHANGELOG/DEVELOPMENT   四件套
└─ .gitignore            忽略 _check.js
```

生成产物 = 一个文本图层 + 3 个滑块效果(数值/步进/小数位)+「数值」滑块两帧关键帧 + 源文本表达式。表达式按效果序号引用,与添加顺序一致。

## 三、关键问题与方案(一坑一篇)

### 问题:数字变化时宽度跳动(抖动)

**TL;DR**:比例字体数字宽度不等("1" 比 "8" 窄),位数变化(99→100)或同位数内变化都让文本宽度变 → 左对齐整行右移、居中绕中心抖,视觉很难看。

- 根因:字体非等宽,且默认左对齐/居中让增长方向双向扩散。
- 解决:①「等宽锁定」强制 `Consolas` 等宽字体(每位等宽零抖动);② 对齐选「中/右」让增长只朝一个方向;③ 字距作为统一加宽控制(等宽下保持均匀)。三者组合彻底稳定。
- 预防:面板默认勾选等宽锁定、对齐默认「中」;比例字体场景在 README 明确提示仍会微抖,须配等宽。

### 问题:生成后无法调整(要可滑块修改)

**TL;DR**:用户要求生成的动画事后能用滑块改。若直接烘焙 sourceText 关键帧,无法整体调速。

- 根因:烘焙 = 每个值写死关键帧,改节奏要重跑脚本。
- 解决:改用**表达式 + 滑块驱动** ——「数值」滑块关键帧 = 时间轴(拖即改节奏),源文本表达式实时算 `snapToStep → formatNumber(小数/前后缀)`;小数位/步进也做成滑块,改即即时变,不用重跑。
- 预防:新增控制项若需"事后可调",优先做成滑块效果而非烘焙常量。

### 问题:表达式与纯函数逻辑重复(两处同步)

**TL;DR**:格式化逻辑既在 `formatNumber`(node 可测)又在 sourceText 表达式(`buildExpr` 拼接)各写一份,改一处易漏另一处。

- 根因:表达式运行在 AE 表达式引擎(ES3),无法 require 本文件,只能拼接字符串复制逻辑。
- 解决:约定 `formatNumber` 与 `buildExpr` 必须**同步修改**,且 `formatNumber` 进 `test_NumCounter.js` 守护(逻辑一致由测试间接保证 —— 改表达式须手动对照纯函数)。
- 预防:AI/维护者改格式化时先改 `formatNumber` 跑测试,再按相同逻辑改 `buildExpr`。

### 问题:缓动手感未经真机验证

**TL;DR**:`applyEasing` 用 `KeyframeType.BEZIER` + `KeyframeEase(0, influence)` 实现缓入/缓出/缓入缓出,但本机无 AE,语义(哪端慢)按标准 recipe,**手感需真机确认**。

- 根因:缓动依赖 AE 关键帧插值,无法在 node 验证。
- 解决:全部包 try/catch,失败退化为线性,计数动画照常;缓动为锦上添花,不影响核心功能。
- 预防:真机验证后若手感反了(如缓入/缓出颠倒),在 `applyEasing` 调换 a/b 即可,无需动其他。
