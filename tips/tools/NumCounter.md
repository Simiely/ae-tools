# NumCounter · 使用技巧

> 适用版本：AE 2026（26.0）中文版
> 相关插件：NumCounter（`panels/NumCounter/`）
> 创建：2026-09-18 · 更新：2026-09-18

## 一句话记住核心设计

> **「数值」滑块的关键帧 = 动画时间轴；sourceText 表达式 = 实时格式化。**

所以「改节奏」永远不是重跑脚本 —— 拖滑块关键帧就行。

## 常用操作速查

| 目标 | 操作 |
|---|---|
| 0→100 递增 | 起始 0 / 目标 100 / 帧数 30 / 步进 1 / 生成 |
| 每 10 跳一次 | 步进填 10 |
| 保留两位小数 | 小数位填 2 |
| 带单位 | 前缀 `$` / 后缀 `%` |
| **改动画节奏（事后）** | 选中文本图层，拖「数值」滑块的**关键帧** |
| **改小数位 / 步进（事后）** | 直接拖对应的**滑块值**，显示即时变 |
| 存 / 调参数组合 | 「存储预设 N」/「使用预设 N」（空槽自动灰掉） |
| 还原默认 | 点「重置」 |

## 进阶用法

### 1. 事后调节奏：只动关键帧，不动参数

生成的文本图层上有三个滑块效果：**数值 / 步进 / 小数位**。

- **数值**滑块上有一串关键帧 —— 那才是"动画曲线"。想让数字先慢后快，
  直接选中关键帧按 F9 缓动，或手动拖关键帧位置
- **小数位 / 步进**滑块是**即时生效**的显示参数，跟关键帧无关

⇒ **不要把"改节奏"理解成"重新生成"**，那会丢掉你已经调好的关键帧。

### 2. 步进：它是"吸附粒度"，不是"每帧步长"

这是最容易误解的一点：

- 步进填 10、目标 100 → 显示 **0 / 10 / 20 … / 100**
- 但底层数值仍然**按帧数连续插值**（线性或缓动）
- 显示值只是取整到 step 的最近倍数

⇒ 步进 = **显示层的最小单位**，不会改变动画时长或节奏。

### 3. 消除数字抖动

数字变化时宽度跳动，根因是**比例字体的数字宽度不等**（"1" 比 "8" 窄），
位数变化（99→100）或同位数内变化都会让文本宽度变。

插件的根本方案是 **v0.2.0 起的「独立数位 / odometer」架构** ——
每位数字是**固定槽位的独立文本图层**，只截取自己那一位，邻居不动。
所以**任意比例字体（含思源黑体 / Arial）计数也零抖动**。

在此之上还有两个**辅助**稳定手段（推荐一起用）：

1. **等宽锁定**（默认开）：强制 `Consolas`，字距更均匀
2. **对齐选「中」或「右」**：让增长只朝一个方向，观感更稳

### 4. 缓动作用于关键帧

「缓动」下拉（线性 / 缓入 / 缓出 / 缓入缓出）改的是**生成时写入的「数值」滑块关键帧**，
不是面板上的某个显示参数。

> ⚠️ 缓动的**手感**（哪端快哪端慢）依赖 AE 关键帧插值，无法在脚本外验证。
> 若真机上感觉缓入 / 缓出反了，反馈即可 —— 调换两行参数就能修，不影响其他功能。
> 缓动失败会自动退化为线性，计数动画照常。

### 5. 预设跨工程复用

- 4 个槽位存在**工程所在目录**的 `NumCounter.presets.json`（跟随工程走）
- **存储前必须先保存工程**
- 「导出 / 导入」可跨工程搬运参数组合

## 踩坑记录

**Q：生成成功但数字一动不动？**
先确认时间指示器在关键帧范围**之内**，再确认文本图层有「数值」滑块。
若面板提示生成成功却毫无变化，属已修复的历史问题（v0.2.4 / v0.2.6），请确认用的是最新版。

**Q：预设「存储」后，「使用」按钮还是灰的？**
历史问题，v0.2.9 已定位真正根因并修复：**槽位索引 0-based / 1-based 错位**
（存进了 "0".."3"，读的却是 "1".."4"）。
v0.2.8 曾误判为"需要重绘"，实际不是。

**Q：数字抖动（宽度跳）？**
见上面「消除数字抖动」。核心是 odometer 架构（新版默认就有），
另建议勾「等宽锁定」+ 对齐选「中 / 右」。

**Q：改小数位没反应？**
「小数位」是**滑块效果**，改面板不会回溯修改已生成的图层；
要事后改，**选中文本图层去拖它的「小数位」滑块**。

**Q：保存预设报错？**
v0.2.5 起预设改为工程目录文件（避开会崩的 `app.settings`）。
若仍报错，确认工程已保存过（Ctrl+S）—— 没保存的工程没有目录可以写。
